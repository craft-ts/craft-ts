# Send context to an AI webhook

`provideSendContextToAi` is copy-only by default. Configure an endpoint to make
the default chat send its generated context directly from the browser:

<<< @/tests/snippets/guide/ai/send-context-webhook.spec.ts#configuration

The primary action is then `Send`. The request is a JSON `POST` with this
versioned shape:

```json
{
  "version": 1,
  "prompt": "# Instruction\nInvestigate this screen",
  "instruction": "Investigate this screen",
  "selectedElements": [],
  "events": [],
  "snapshot": [],
  "captures": {},
  "component": {
    "hostName": "OrdersPage",
    "tagList": ["component:OrdersPage#1"],
    "coords": { "x": 120, "y": 80 },
    "outerHTML": "<section>…</section>"
  }
}
```

`prompt` is the Markdown generated from the other fields and the selected
options. `component` is omitted when the chat was opened from the launcher
without a captured component. `captures.component` and `captures.page` are
present only when their corresponding DOM/CSS options were selected. Timeline
events generated by the webhook itself are excluded from later payloads.

## Success and failure

Any `2xx` response is successful, including `200`, `202`, and `204`. Network
failures, timeouts, and non-`2xx` responses show an error in the chat. The
failed request is never copied automatically. `Retry` sends the exact same
payload again, while `Copy payload` copies that same JSON only after the user
asks for it. `Copy JSON` remains the separate timeline export action.

Without `endpoint`, the primary action remains `Copy prompt` and no webhook
request is made.

## Browser and security constraints

The endpoint must allow the browser application's origin through CORS, and it
must accept a JSON `POST`. The URL is application configuration shipped to the
browser: it is not a secret. This first version has no configurable headers or
secret storage, so use a protected intermediary when the receiving agent needs
authentication.

## Complete integration example

The frontend can point at a same-origin proxy or an explicitly CORS-enabled
agent gateway:

```ts
// app.config.ts
import { provideSendContextToAi } from '@craft-ts/component';

export const providers = [
  provideSendContextToAi({
    endpoint: 'https://agent.example.com/hooks/context',
  }),
];
```

The gateway validates the version, forwards the Markdown prompt and structured
context to the agent, and acknowledges the webhook with any `2xx` status:

```ts
// agent-gateway.ts (illustrative Express endpoint)
app.post('/hooks/context', express.json(), async (request, response) => {
  const payload = request.body as {
    version: number;
    prompt: string;
    instruction: string;
    selectedElements: unknown[];
    events: unknown[];
    snapshot: unknown[];
    captures: Record<string, unknown>;
  };

  if (payload.version !== 1 || typeof payload.prompt !== 'string') {
    response.status(400).json({ error: 'Unsupported context payload' });
    return;
  }

  await agent.run({
    prompt: payload.prompt,
    context: {
      instruction: payload.instruction,
      selectedElements: payload.selectedElements,
      events: payload.events,
      snapshot: payload.snapshot,
      captures: payload.captures,
    },
  });
  response.sendStatus(202);
});
```
