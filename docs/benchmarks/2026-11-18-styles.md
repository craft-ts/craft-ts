# Styles compilés et enfants stylés génériques

18 novembre 2026. Les styles sont retenus pour les plans `lean` : compilation directe des callbacks et générateurs de style, ou conservation d'un élément stylé générique à l'intérieur d'un parent compilé. Les autres expressions de style à la racine gardent le composant générique. Le plugin reste optionnel et le mode standard conserve ses replis.

Les [données](2026-11-18-styles-summary.json) archivent **344 navigations finales et 40 navigations de confirmation**, les sources exactes, patches, empreintes, contrats et contrôles. Une première série de 264 navigations est conservée comme prototype invalidé. Une tentative de démarrage antérieure s'était arrêtée sur les types d'une variante après la cohorte page ; elle est distinguée des mesures finales.

## Deux voies, mêmes helpers de style

Un callback littéral ou un générateur `style: function* () { ... }` devient un binding direct. Le runtime réutilise `resolveStyleBindingValue`, la comparaison superficielle des valeurs, `applyStyles` et la politique de sécurité injectée. Les générateurs de style restent interprétés : leur conduite et leur contexte ne sont pas remplacés par un lowering spécifique.

Les expressions évaluées pendant le template gardent leur ordre source. L'ordre d'application des bindings est séparé : attributs, puis classes, puis style pour chaque élément. Les retours objet, chaîne, suppression, propriétés CSS personnalisées et fonctions imbriquées passent par les règles génériques. Un style résolu inchangé ne réécrit pas le DOM ; le contenu existant est conservé.

Un descendant dont le style ne peut pas être compilé reste un élément générique dans un trou du plan. Cela permet de compiler son parent et de spécialiser sa liste. Les lectures faites pendant son patch natif, notamment les getters de propriétés, doivent rester suivies ; les effets des bindings eux-mêmes restent indépendants. Ce suivi supplémentaire utilise l'ABI **4**, les bindings directs l'ABI **3**. Un runtime qui ne connaît que l'ABI 2 ignore ces plans et conserve le template original. Les deux replis sont vérifiés dans le navigateur : 202 commentaires pour le contrat de 100 lignes, contre 2 avec les listes spécialisées.

Les inputs objet ou callback qui imposent un propriétaire conservent également le composant générique. Les exclusions habituelles de développement, SSR, hydratation, boundaries et diagnostics restent actives.

## Échecs reproduits, correction et validation

Le premier prototype passait 136 tests Compiler et 609 tests Component et gagnait sur les listes. Trois nouveaux contrats l'ont invalidé : deux getters de styles perdaient leurs dépendances lors du patch générique, et un binding natif restait abonné après une erreur initiale. Le suivi des trous a été corrigé avec l'ABI 4. Le [nettoyage du premier rendu](2026-11-18-initial-binding-error.md), également nécessaire sans plugin, est livré séparément.

Le candidat intégré passe **139 tests Compiler** et **612 tests Component**. Les contrats couvrent le moteur CSS, les origines autorisées à l'initialisation et après changement, CSS exécutable et URLs refusés, ordre d'application, getters, abonnements, DOM conservé, listes réordonnées, clone/create, et les replis avec propriétaire. Les six candidats finaux passent TypeScript ; les vérifications intégrées de Compiler, de ses specs et de Component passent aussi.

Les **80 comparaisons** de génération couvrent treize sources originales et sept fixtures extraites des runners réellement mesurés, dans quatre configurations. Le code généré et les décisions sont identiques octet par octet ; les sources runtime correspondent après formatage. Le lint ciblé n'ajoute aucune erreur et les nouveaux tests en ont zéro. Les six erreurs runtime historiques restent explicites ; le contrôle NX est ignoré faute de graphe en cache.

```sh
node apps/compiler-benchmark/experiments/styles.mjs
node apps/compiler-benchmark/experiments/validate-styles.mjs --final
node apps/compiler-benchmark/experiments/run-styles.mjs --final
PAGE_RUNS=20 PAGE_ITERATIONS=3 PAGE_SCALES=2 PAGE_COMPILER_OPTIONS='{}' CAMPAIGN_OUTPUT=styles-final-page-confirm node apps/compiler-benchmark/experiments/run-page.mjs style-cleanup style-final
ATTRS_INTEGRATED=true ATTRS_VALIDATION_PREFIX=styles-integrated node apps/compiler-benchmark/experiments/validate-attrs-watched.mjs
npx tsc -p libs/compiler/tsconfig.lib.json
node apps/compiler-benchmark/experiments/validate-styles-integration.mjs
node apps/compiler-benchmark/experiments/validate-styles-lint.mjs
node apps/compiler-benchmark/experiments/archive-styles.mjs
```

L'archivage consomme aussi les premières séries et les tests rouges conservés dans les données publiées. Les microbenchmarks utilisent des blocs adjacents équilibrés et un mélange à graine fixe ; les contextes navigateur sont neufs. Aucun test ou build indépendant n'a tourné pendant les mesures. Le tas après GC exclut la mémoire DOM native ; JS/DOM ne mesure pas LCP/INP et les temps de build dépendent des caches et de l'ordre. Les limites déjà documentées d'observation du DOM connecté au premier montage et les compromis de `lean` restent applicables.

La piste « styles, attrs et helpers » est désormais mesurée. Les autres pistes en attente et le marquage de services encore partiel restent dans le même objectif de campagne.
